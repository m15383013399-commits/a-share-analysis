# A股分析平台：采集与分析重构方案

日期：2026-09-21。状态：方案，尚未开始重构或发布。

## 1. 产品范围与取舍

面向个人 A 股研究，完成一条可核查的流程：采集数据 → 判断是否可分析 → 生成判断与预测 → 下一交易日对照实际结果。

主导航只保留「数据中心」「分析工作台」。模型、凭证、采集计划放在设置中，历史报告和复盘放在分析工作台内。不做股票筛选器、模拟交易、学习中心、实盘下单、多用户权限平台。

分析支持两个入口：

- 收盘研究：延续六指数事实、四核心指数预测、3–5 个板块代理、滚动五股、独立黄金价格研究及昨日逐项复盘。
- 指定标的研究：用户输入股票或指数代码，按所选范围准备历史行情、财报与事件资料。它是单独的研究报告，不自动改变正式五股关注池或日预测台账。

删除股票筛选功能不等于删除既有五股复盘；关注池保留为研究对象清单。继续标注“不构成投资建议”。

基于本项目已有 `market_diary` 能力开发新的界面与服务，不复制 CN 的专有 `app/`、`frontend/` 及其素材。后续公开仓库暂定 `a-share-analysis`；仅在实施、验证和发布检查完成后创建。现有 CN 部署暂时独立保留。

现有目录实际发现 8 份 snapshot、9 份 forecast，最新日期为 2026-09-10；存在日期缺口。迁移时展示缺口，不按背景描述假定台账完整，更不补造缺失预测。

当前预测校验与最新项目约定有差距：区间未禁止跨 0、板块区间可缺、股票概率和失效条件未强制、active 状态未严格限制。登记入口目前也缺少同日文件不可覆盖的保护。上述事项必须先修复；历史文件按其原始版本读取，不为通过新校验而改写。

## 3. 数据中心

### 用户能看到什么

以数据集为主表，而不是只显示“某供应商已连接”。每行显示：研究对象、数据截至时间、上次采集时间、来源、覆盖范围、质量状态、失败原因和可执行动作。

操作保留：测试连接、采集最新、补指定范围、查看证据、重试失败项。测试连接成功不等于行情完整或可用于正式收盘分析。

### 数据范围与优先级

| 数据集 | 一期安排 | 可用性要求 |
| --- | --- | --- |
| 六指数、全市场广度、成交额 | 使用现有腾讯/新浪/备选适配器 | 供应商日期、市场范围和单位一致；主链失败不能用旧值顶替 |
| 行业与主题代理 | 延续现有行业/概念来源 | 绑定来源与代码，不将同名板块视为同一时间序列 |
| 个股/指数日线 | 先覆盖四指数、五股及用户指定标的；建议近 250 个交易日 | 标记原始价/复权口径、除权因素与停牌；窗口不足则不计算所需指标 |
| 财务与估值 | 按标的增量采集；必要时配置有权限的数据服务 | 财报期、公告日、数据可用时间分别记录；不能把后来的重述值送入早期分析 |
| 公告与新闻 | 公告、监管与政府信息优先，新闻用于解释催化 | 直接链接、发布时间、抓取时间、正文摘要与关联标的；没有证据不补写催化 |
| 黄金本体 | 独立采集 XAU/USD 及 Au99.99 或上海金基准资料 | 明确品种、单位、时区和盘中/延时/收盘；不与黄金股混用 |

供应商按“具体接口 × 数据集”做实测验收。AkShare 是适配工具，底层若仍来自同一网站，不能算两个独立交叉验证来源。价格、成交额或市场范围不同的回退结果必须先完成口径匹配。

免费数据先满足基础研究，付费源作为可选增量；不承诺免费接口永久可用。公开发布代码时不默认公开抓取的行情与新闻全文。

### 统一证据合同

为每份采集记录保留：`dataset`、`instrument_id`、`provider`、`upstream_source`、`requested_date`、`provider_timestamp`、`date_verified`、`fetched_at`、`timezone`、`unit`、`adjustment`、`available_at`、`raw_hash`、`parser_version`、`quality_result`。

其中 instrument_id 包含资产类型、交易所/市场和代码，防止同码异义。available_at 记录当时何时真正可见；没有可验证时间的资料不进入严格历史重放。请求记录去除 Token、Cookie 等凭证；证据保留必要响应，不抓取与研究无关的个人数据。

目标日期、供应商日期与抓取时间必须分开。当前部分新浪/AkShare 解析结果采用请求日期，不能将这一赋值当作供应商日期证据。新数据应明确日期核验能力；旧快照保持原始判定并附审计说明，不事后制造证据。

存储分为：供应商原始响应 → 标准化数据 → 通过质量门的快照。旧 A 股正式 snapshot 仍使用原 11 键合同；新闻、财务、黄金和数据清单存放在旁侧 evidence/manifest 文件中，通过快照哈希关联。

### 错误与执行规则

- 必需 A 股行情缺失、过期或不稳定：阻止新的正式收盘分析、评价和预测；旧报告可以查看，但醒目标注其原日期。
- 可选资料缺失：列明缺口并省略相应论断。缺少财报时不能编造估值或基本面；若正式报告必需章节无法完成，整份报告标记“研究不完整”。
- 黄金等独立数据失败不改写 A 股行情状态；对应章节显示不可用，不输出伪造预测。
- 按源设置超时、限流、有限重试；只重试失败数据集。跨源冲突保留差异与最终选择依据。
- 每个来源返回后先做数据集级完整性检查，通过后才选用；不能像现有部分路径那样遇到非空结果就停止回退。所有来源均不合格时保留失败，不降低质量门。
- 任务持久化排队、执行、校验、成功、失败、取消、中断状态；“等待收盘”与“连接失败”分开显示。
- 交易日收盘后默认触发建议为 15:20，仍以稳定性门为准；开关由用户设置。电脑休眠会中断任务，恢复后不把当前报价当作漏跑日历史收盘。
- 当前日历只有 2026 年；界面显示覆盖范围，跨年先更新并审核日历，不能自动猜交易日。

## 4. 分析工作台

### 使用流程

进入默认显示最近一次报告和它的日期、数据覆盖、昨日预测评价。主要动作是「生成收盘分析」，旁边提供「分析指定标的」。选定日期或标的后先显示数据就绪情况，缺什么可以直接补采。

分析先冻结输入数据，再运行模型。模型生成过程中不自行切换行情源或修改快照，外部文章视为待分析资料，不能当作运行指令。

正式主流程：

```text
采集与质量门
  → 固定快照和证据清单
  → 计算指标、评价上一交易日预测
  → 主分析生成判断及结构化预测草稿
  → 反证检查与程序校验
  → 登记下一交易日预测
  → 保存报告，显示“已入账”与版本
```

只有原 CLI 注册入口成功返回 0 才算正式入账。报告生成成功但登记失败时，只保留草稿并显示校验问题，不能显示“全部完成”。

服务层和 worker 也必须检查 `market_status=ready` 且 `quality_status=passed`，不能依赖网页按钮或某次 CLI 已检查过。盘中/样例数据不进入这条正式流程。

### AI 分工

一期默认一次主分析、一次审阅；发现可修复问题时最多一次修订。主分析覆盖量价、基本面、事件和风险；审阅寻找证据缺口、与数据矛盾之处及替代解释。暂不增加多个角色反复辩论。

可配置模型服务、模型名称、单任务 token/费用上限。费用以服务返回用量为准，价格未知时只显示 token 及“费用未知”。失败保留已完成步骤，重试复用同一证据包；更换模型或输入必须形成新版本。

程序负责涨跌幅、成交额、技术指标、区间中点、命中率与 MAE。AI 负责解释、情景和反证；每条事实绑定证据，推断单独标注。程序校验可以保证结构和数值一致，不能保证市场推断正确。

### 报告内容

1. 结论和关键证据，区分事实与推断。
2. 六指数、成交额、广度及相对上一交易日变化；缺前日数据时明确注明。
3. 四核心指数的次日与一周判断、三方向概率、预测区间及失效条件。
4. 3–5 个板块代理的口径、催化、持续性和风险。
5. 原五股逐一复盘、六因素及保留/替换依据；普通日最多替换两只，最终恰好五只 active。
6. 独立黄金价格研究；没有独立预测评分合同之前不并入股票板块评分。
7. 昨日每项预测和今日实际、偏差、方向/区间命中及累计 MAE；不可评价项和缺口同样展示。

历史区增加概率校准所需的样本记录，样本充分后再看概率是否可信；一期不把模型自报概率展示成经验证的准确率。一周观点先作情景研究，未建立独立到期规则前不混入次日评分。

### 预测版本与防重跑

新预测使用明确版本的严格合同：所有项目必须具有同号且非零的上下界、中点、概率和失效条件；股票必须有六因素。低置信度用概率与证据不足表达，不靠跨零宽区间遮掩。

同日正式预测首次成功入账后锁定。相同内容重复提交按幂等成功处理；不同内容拒绝覆盖，可另存非评分的研究草稿。后续若要支持修正，必须设计修订链和生效时间，不能追溯性改变已评分预测。

## 5. 界面设计

场景：个人用户在桌面浏览器收盘后查看结果，希望快速知道“资料够不够、判断是什么、昨天哪里错了”。采用浅色、清晰表格和报告正文；以常见文档阅读和任务状态列表为参考，不照搬 CN 页面。

左侧只放两个入口；顶部显示当前研究日期、采集状态与设置。数据中心以可排序明细表为主；分析工作台以报告正文为主，来源侧栏按需展开。红涨绿跌同时显示正负号，任务成功/失败另配图标和文字，避免与行情颜色混淆。

关键状态：首次无数据引导采集；缺密钥只阻止 AI 步骤；抓取失败显示具体数据集及重试；收盘未稳显示何时可再试；模型超时保留进度；历史缺口直接标日期；无财报/新闻不以空白卡片或零值掩饰。小屏折叠导航，宽表可横向滚动。运行步骤只显示采集、校验、分析、审阅、保存等有意义的状态，不展示模型内部思维过程。

## 6. 建议技术结构

采用模块化单体：独立新写 Vue + TypeScript 界面、Python/FastAPI 服务和一个顺序执行的 worker。API 接收任务返回 task_id，worker 执行采集、模型和登记，前端查询状态。

初期让 worker 以独立子进程调用已有采集 CLI；现有 AkShare 超时使用 SIGALRM，不直接塞进 Web 后台线程。子进程由任务总超时和取消机制管理，进度及产物再回写任务表。

SQLite 存设置、任务与报告索引，JSON/JSONL 保留正式台账，原始响应及历史批次写文件。SQLite 仅由受控任务路径更新，正式台账目录设置跨进程写锁，防止浏览器重试和定时任务同时写入。SQLite 索引可从已落盘文件重建；写入步骤保留日志，重启后按文件和哈希对账。

SQLite 与证据文件放在本机磁盘，备份包含一致的数据库与文件清单；不能直接把工作数据库放网络共享盘。WAL 允许读写并发，但仍只有一个写入者，见 [SQLite 官方说明](https://www.sqlite.org/wal.html)。

长期任务采用持久化任务表和独立 worker，不仅依赖 API 进程内回调；[FastAPI 官方文档](https://fastapi.tiangolo.com/tutorial/background-tasks/)将进程内 BackgroundTasks 用于响应后的任务，并提示较重的工作可考虑独立执行工具。这里按个人单机规模先实现可恢复的小型 worker，未来确有多机需求再换队列。

本地 Python 环境与 Docker 二选一均可运行。Docker 目标为两个同版本镜像服务（Web/API、worker）加持久卷，静态网页由服务提供；一期不需要 MongoDB、Redis 或独立 Nginx。发布源码不等于把服务暴露到公网；默认本机访问，保持基础登录、凭证只在服务端存储。

目录建议：`backend/`（新服务）、`frontend/`（新界面）、`research/`（整理后的现有业务模块）、`tests/`、`docs/`。运行数据在独立 runtime 目录且不入 Git；旧项目通过兼容适配或只读导入延续。

## 7. 分阶段实施及验收

| 阶段 | 交付 | 必须通过的验收 |
| --- | --- | --- |
| 1：数据与台账底座 | 收盘采集任务、数据中心、证据留存、严格新预测合同、防覆盖、历史只读导入 | 失败/过期不会产生正式预测；同日重跑不覆盖；旧评价可读且保留原日期缺口 |
| 2：完整收盘分析 | 一键采集到报告、主分析与审阅、预测登记、逐项昨日复盘、黄金独立章节 | 数字与快照一致；每个旧预测都有实际/不可评价状态；模型或登记失败不显示完成；关注池约束通过 |
| 3：指定标的深入分析 | 有限历史日线、财报、公告证据链、按标的分析与版本对比 | 不混复权口径；资料以当时可用时间过滤；不改动正式日预测；计算指标有足够数据窗口 |
| 4：公开交付 | 一键启动、合成演示数据、README、安装说明、来源与许可证说明 | 全新环境可运行；仓库不包含 CN 专有代码、密钥、本机账号、日志或真实研究台账 |

阶段 2 所需最少历史/事件数据可提前于阶段 1 接入；阶段 3 扩充的是深度与按需研究入口，不以缺失资料生成虚假的完整分析。

核心验证采用既有离线 fixtures 加新的失败场景：供应商超时、旧日期、同名异码、重复请求、模型无效 JSON、无依据数字、跨零预测、注册失败、进程中断及评分幂等。最后以新旧数据隔离的试运行验证端到端流程。不开收益承诺，不以一次报告流畅或单日命中作为验收标准。

Qlib 暂不作为一期运行依赖。待历史数据连续、复权与时间可用性可靠后，再用独立实验目录验证信号，结果与正式预测评分分开。

## 8. 实施默认值

按个人本机使用、收盘研究优先、免费基础行情优先、凭证按需配置执行。保留现有正式数据并建立备份与导入清单，先运行新平台验证，再考虑停止旧 CN。实际模型、付费数据权限及公网部署在需要时单独配置，不阻碍方案成立。

不构成投资建议。
